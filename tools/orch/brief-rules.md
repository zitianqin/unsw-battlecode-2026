Standing rules for every subagent brief (append to each; the brief itself adds the task's own context: what, why, the history and decisions behind it, exact files/branches/commits, what reviews already found, what's out of scope):
- Read ~/.bc-loop/briefing.md first: what research assumes, each line with its source and date; it overrides older notes, memory and earlier findings (REFLECT 2026-09-30 09:12 F4: a rule sig gave reached only the studies told it by hand).
- Repo: the main checkout (<repo>); read CLAUDE.md first (rules + "LOOP.md: <heading>" pointers into loop/LOOP.md).
- Own worktree/branch named in the brief; only writer there. Never push, never merge into main.
- Tests: besides the touched modules, always run loop/test_home and loop/test_launches (repo-wide rules: live-path literals, claude launches), since a new file can break them untouched (2026-09-28: why.py and watch.py merged with a live-path literal).
- Tests: focused only, `PYTHONPATH=loop <repo>/tools/gated_test.sh <repo>/.venv/bin/python -m unittest <module>` (worktrees have no .venv; the gate waits for the load share). Never whole-repo tests or type checkers. Tests never touch ~/.bc-loop. New regression tests must fail before the fix.
- Git: git-config authorship only (no --author, -c user.*, GIT_AUTHOR_*), never --no-verify; the pre-commit hook must pass. Commit messages end "Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>".
- ~/.bc-loop is live state: read freely, never write unless the brief says so. Ideas only via meta.append_ideas / driver.mark_idea.
- Never run the browse binary or tools/discord_read.py for real (sig's signed-in Discord window is the main checkout's daemon). Never fetch Discord/GitHub links.
- Never kill a process you didn't start. No credentials printed or committed (~/.unswbc never read).
- A change updates every doc describing it (grep names/numbers in CLAUDE.md, loop/LOOP.md, prompts); CLAUDE.md/LOOP.md have byte caps (tools/doc_size.py).
- MISSES numbering: take the next number after the last on main; say so in the report, since branches in flight may take the same one. Main moves often: merge main into your branch before finishing.
- Out-of-scope findings: report, don't fix. Final report: commits, what changed, tests run and results, known weaknesses.
- A build made from sig's suggestion quotes his words verbatim as its scope, and lists anything it leaves out with a reason (REFLECT 2011 F4).
- A change to what coders can reach (sandbox allow-lists, ssh config, tools named in coder prompts) is tested under the coder's real sandbox, or with a short real coder session, before it merges (MISSES 54; REFLECT 2011 F8).
- Replay findings (MISSES 64): an end-reason or place count (hitWall, hitSelf, deaths in a pocket) is never a diagnosis. For any finding about deaths or losses, rebuild the sequence: find the round the dragon became doomed (reachable room below its length, no exit) and what caused it, watch at least 3 cases with `tools/watch.py dragon` and `frames` at that round, and state the mechanism with its count. Once it exists, `watch.py doom` gives the table.
- A map or loss study that finds "our local tests can't show this" names the missing local opponent (or rotation change) and queues it, or says why not (REFLECT 0105 F8).
- Generalise (sig, 2026-09-28; the text is meta.GENERALISE in loop/meta.py): no hand-picked values, thresholds or rounds. Use observed inputs or fitted models with full inputs, judged on held-out maps: each official map left out with its near_* copies, worldgen maps, and maps new to the pool. A result that holds only on our generator is a finding, not a pass.
- Effort and review (sig, 2026-09-29): work at medium effort, never high. A simple change unlikely to break anything (a flag or number flip, wording, prompt lines) needs no review of your own; locking, queue order, verdicts and gates still do.
- Leader games (sig, 30 Sep): study other teams only from their recent ranked games, split by submission id, and name the submissions used. Teams play worse bots unranked, and some run weaker bots even in ranked games to hide ideas, so compare against a team's best recent ranked submission and treat a sudden style change as a possible decoy.
- A finding about a group of teams ("the leaders cross more", "the top 5 do X") gives a per-team table: team, n games, the submission ids they come from, and that team's own measure; then names the teams the finding rests on. A team with too few games counts for nothing (REFLECT 2026-09-30 09:12 F5: Stockfish, rank 1, had 1 game each on Portals and Trauma in a "top 5" finding).
- A study's report (a leader, opponent, teammate-loss or any replay study) numbers each finding `- S1. <finding>` (a main one `## S1. <title>`), with its n and chance. The orchestrator saves the report whole to ~/.bc-loop/reports/<YYYY-MM-DD-HHMM>-<name>.md in the same response, so health.undecided alerts until each S id has a decision in decisions.md (REFLECT 2026-09-30 15:13 F10: the teammate-loss study's shut-in gap against cheji, p 0.001, got no idea until sig raised it).
- A study of other teams' games ends its report with a `Sources:` line: the replays used, by submission id, ranked games only, each submission used or ruled out with a reason (too few games, a possible decoy, an old build). Decoded sonar only when sig asks for it, as understanding of their play, never as an idea's input (F6).
